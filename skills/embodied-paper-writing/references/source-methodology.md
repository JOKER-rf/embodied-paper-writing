## 从文章观点转成写作行为

| 提炼出的路径 | 原文启发 | 写作时应做的事 | 防止误用 |
| --- | --- | --- | --- |
| 机制诊断 | 先解释失败现象，再引出方法 | 提出竞争解释，设计区分它们的对照 | 消融有提升不等于找到了唯一根因 |
| 默认假设重审 | 检查行业惯用设定是否必要 | 明确旧假设成立的条件与新方案的适用范围 | 不虚构“所有方法都假设……” |
| 理论解释 | 用形式化连接经验与机制 | 陈述假设、命题、证明及其对实验的可检验预测 | 不用无关引理装饰算法 |
| 诊断基准 | 把隐蔽缺陷变成可测问题 | 定义构念、任务、测量可靠性与数据防泄漏协议 | 新数据集不自动构成新科学问题 |
| 真实效用 | 将技术目标连接实际需求 | 测量相关方关心的成本、收益、约束和失效代价 | 应用愿景不能当已实现社会影响 |
| 统一机制 | 用较简洁机制解释多种能力 | 界定共享部分、任务特定部分与复杂度代价 | 统一接口不自动等于统一学习机制 |

## 六类路径的证据要求

### A. 机制诊断

推荐链条：现象 → 候选解释 → 区分性实验 → 设计约束 → 针对性改进 → 改进与解释是否一致。

具身示例：长时程操作失败可能来自状态记忆不足、视觉遮挡或动作延迟。先分别控制历史长度、遮挡与延迟，再决定是否提出记忆模块。若同时改变模型大小与输入帧数，不能将改善全部归因于记忆。

证据不足时写“结果支持这一解释”，并说明仍未排除什么；不要先宣布根因，再为方法寻找佐证。

### B. 默认假设重审

推荐链条：普遍采用的具体约束 → 在目标条件下的代价 → 替代设计 → 保持其他预算的比较 → 原假设仍有优势的条件。

具身示例：检验固定动作块长度是否适合所有接触阶段。比较固定和自适应方案时同时报告控制时延、平滑性、成功率及调用预算。若优势只在高速接触任务出现，应直接说明范围。

反例很有价值：若简单旧方案在低延迟环境同样有效，就把论文定位为条件性改进。

### C. 理论解释

推荐链条：可形式化问题 → 假设 → 命题 → 证明 → 实验可检验推论 → 理论与真实系统的差距。

具身示例：在给定动力学误差与有限时域的假设下推导规划误差上界，再检查预测步长增加时误差趋势。不能把简化模型中的界推广成开放环境机器人安全保证。

如果只有直觉推导，标为分析或命题猜想。经验充分而无定理时，不必改造成理论论文。

### D. 诊断基准

推荐链条：现有评测漏测的能力 → 操作性定义 → 任务生成/标注 → 指标效度 → 多类基线 → 稳定失效模式与边界。

具身示例：用对象身份、语言组合、场景与动力学的独立变化测量不同泛化轴；报告哪些轴只做到部分隔离。训练与测试不能来自同一轨迹的相邻帧。

除排名外，说明指标是否与真实闭环任务效果相关，以及难度设置是否偏向某个模型家族。

### E. 真实效用

推荐链条：明确用户与使用条件 → 可量化需求 → 技术设计 → 场景有效性 → 成本及失效后果 → 未覆盖人群/环境。

具身示例：辅助取物系统除了成功率，还可能需要报告人工接管、完成时间、失败恢复和部署限制。实验室演示只能支撑可行性，不能证明日常照护收益或用户满意度。

不编造用户研究、伦理审批、需求访谈或落地规模。未做的影响分析可作为动机与未来工作。

### F. 统一机制

推荐链条：原方案重复承担的功能 → 共用表示/接口的定义 → 任务如何映射 → 与专用方案的公平比较 → 负迁移与资源代价。

具身示例：统一多本体动作表示需说明坐标、单位、自由度映射、有效动作掩码与各平台适配器。共享主干但新增多个任务头时，应精确描述“共享表示”，不写成完全无任务特定设计。

比较参数量、总训练数据和计算量；报告某些平台性能退化时的原因，不能只挑受益任务。

## 如何选择

以现有证据最强的一条作为主线：已有干预诊断适合 A，已有可信理论适合 C，已有测量设计适合 D。只因标题更吸引人而选 B，会造成结论与实验脱节。

写一张短卡即可：核心观察、主要主张、选择路径、支撑证据、最强竞争解释、可否定主张的结果。然后将这张卡转化成引言和实验结构。若证据只支持渐进改进，就准确写出其价值。
