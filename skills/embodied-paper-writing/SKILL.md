# 具身智能顶会顶刊论文撰写

帮助作者把已完成或正在开展的研究写成可核验、可复现、有明确贡献边界的论文。以用户材料为事实依据，以目标会刊当期官方要求为格式与政策依据。默认中文讨论、英文论文正文；用户指定语言或只要求局部修改时遵从其范围。

本 skill 的叙事框架改编自用户指定的微信公众号文章；出处、提炼边界见 [source-methodology.md](references/source-methodology.md)。具身评测与会刊适配是独立补充，不声称来自原文。

## 使用方式

显式调用 `$embodied-paper-writing`，说明目标会刊、工作阶段、材料位置和想得到的产物。例如：

```text
使用 $embodied-paper-writing。
目标：CoRL，年份待定；阶段：已有方法与初步结果。
材料：./notes/method.md、./results/summary.csv。
任务：先形成论文主线和实验补强方案；不要写成结果已完成的全文。
```

完整的输入清单、七种模式和可复制提示词见 [usage.md](references/usage.md)。缺少材料时可从 [paper-brief.md](assets/paper-brief.md) 收集；不要要求用户先填完整张表才能开始。

## 先建立事实边界

1. 读取用户指定材料与已有稿件。先查看数据定义、日志说明、表头和实验协议，再解释汇总数值；代码可以证明实现，不能独自证明性能。不要顺带读取无关研究目录。
2. 记录研究问题、论文类型、真实完成情况、目标会刊及年份/track、输出格式、现有语言。未指定年份时标为“待定”；需要核对投稿政策时再澄清，不能自动套用历史模板。
3. 复用或建立 [evidence-ledger.md](assets/evidence-ledger.md) 中的相关表格，区分：已验证、用户报告但未核验、解释性假设、计划实验、缺失信息。轻量改句可在回复中简记，不必创建整套文档。
4. 只集中询问会改变结论或阻止所请求产物的少量信息。其他缺口写入待办并继续能完成的工作；无结果可以写问题与方法草稿，结果段使用明确占位符。

### 不可越过的证据边界

- 不编造实验数值、样本量、引用、定理、硬件测试、伦理批准、开源链接或已执行的实验。`[待补：指标/协议]` 只表示缺失，不能替换成猜测。
- 用户报告的结果可保留并注明来源状态；不能描述为已从原始日志验证。推断必须与观测分开。
- 不把相关性写成因果、模拟写成真机、见过的对象写成泛化、更多训练数据写成同预算算法优势、成功演示视频写成总体成功率。
- SOTA、首次、通用、可靠、安全等强措辞只在明确比较范围与证据支持下使用；否则缩小主张。文献核验不足时不能宣称“首次”。
- 叙事用于解释证据，不能替代技术贡献或保证接收、Oral、获奖。原文中的论文奖项与统计不能作为本 skill 已核实的事实。

## 组织论文的论证

### 1. 把研究压成可检验的主张

先用一两句表达：在什么任务与约束下，现有方案存在哪个具体缺口；提出的哪个机制预期改善什么；用哪些证据检验；结论到哪里为止。

给出与最接近工作在问题、假设、训练信号或部署机制上的实质差异，而非只列模块名称。为主要论点分配 C1、C2 等标识，连接实验 E1、E2 和稿件位置。没有证据的贡献改成假设或补强任务。

### 2. 选择适合证据的叙事

按叙事参考，从机制诊断、默认假设重审、理论解释、诊断基准、真实效用、统一机制中选择主线，必要时辅以另一条。不要求每篇论文都反直觉、都有定理或都使用统一接口。

诊断证据不足时用“假设/结果与该解释一致”，不要用“根因已证明”。理论不足时保留经验研究定位。基准型、系统型与方法型论文使用不同贡献结构。

### 3. 让实验回答具体问题

用“研究问题 → 对照/干预 → 协议 → 指标 → 支持/否定条件 → 论文位置”设计实验。优先补足可能改变核心结论的对照，再考虑增加展示性实验。真实预算不足时收窄结论并列出限制。

具身工作明确观测、动作、机器人平台、闭环控制、数据划分、真机/模拟、任务成功判据、干预和统计单位，细则见具身评测指南。

### 4. 写作并适配会刊

按分节写作指南写出用户请求的部分，使用 [manuscript-outline.md](assets/manuscript-outline.md) 作为可选骨架。证据充足时直接写作，不反复要求批准提纲。

会刊定位与规则核验见会刊指南。规则记录需要官方 URL、适用年份/track/阶段、核验日期和未知项。无法联网时仍可写内容，但格式与政策标为未核验。不要把写作偏好当官方审稿标准。

### 5. 自查与交付

依次核对：主要论点有证据、实验公平且解释克制、方法可复现、最近邻文献对比准确、摘要和正文数值一致、表图单位与统计一致、目标规则已核验或明确未知。

交付用户实际要求的文件或正文，并简述实质改动和仍影响结论的缺口。不能仅交付建议而不完成已授权的撰写。局部改写无需附加整篇论文报告；完整论文任务通常附主线、正文、证据缺口和引用/规则核验状态。

## 文件与外部操作

- 延续用户现有 Markdown、LaTeX 或 Word 工程，保留术语、符号、引用键和可编辑性；无格式偏好时先交付 Markdown 正文。
- 若创建文件，将证据状态和待办与论文正文分开，避免把写作批注混成最终稿。未完成稿保留清晰占位符，交付时说明不能直接投稿。
- 创建或编译 LaTeX 时使用当前环境提供的项目/编译工具；没有编译能力则如实说明，不能宣称已编译。其他文档格式按当前环境能力处理。
- 该 skill 支持本地写作与核验；投稿、联系编辑/合作者、公开仓库、上传保密稿件或执行新真机实验需要相应的用户授权，不能从“帮我写论文”推导。
